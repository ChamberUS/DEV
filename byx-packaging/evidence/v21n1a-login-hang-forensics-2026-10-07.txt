V2.1N-1A login hang forensics + fix (2026-10-07). No TX, no private gate, no push, chain untouched. The user's real authority was never used by automation.
evidence from the user's attempt (service.log + audit types/timestamps only): two LOGIN_OK events at the authority (15:50:02Z and 15:51:13Z; one LOGIN_FAILED between = wrong password), service stopped 16 s / 2 min after => the authority and the IPC worked; the failure was AFTER the login, in the panel. The hung process was already closed when forensics started (no live thread dump of the user's session was possible).
reproduction (synthetic, outside the real home): real byx-local-service in its own process with an in-memory synthetic authority (LoginHost) + the panel with the PRODUCTION AppContext (real AuthorityClient) driven through the real login fields/button (RealLoginQa), FX heartbeat. LOCAL_QA + live node, before the fix: shell appears, then the FX 1 s chromeWatch timer throws AccessDeniedException(SERVER_AUTHORIZATION_REQUIRED: wallet.identity) at PanelApp.updateStatusDock:983 (ByxWalletIdentityService.wallets, DENY_ALL) and PanelApp.onUncaught shows the full-window "Something went wrong" overlay; the timer stops.
root cause: since V2.1L the network identity becomes VERIFIED whenever the public chain is LIVE/SYNCING/STALE; updateStatusDock (and the diagnostics report) then read the LEGACY wallet list, which is DENY_ALL since the cutover and throws. Before V2.1L (and with no node) identity was never VERIFIED so the line was never reached. Exposed only by LOCAL_QA + live node (V2.1M onward); not caused by the Chain data rail/route/screen. Not a login/IPC/executor problem.
fix: panel.shell.WalletStatus (denied/any failure => "Wallet unavailable", never an exception) used by PanelApp dock and diagnostics. Hardening: at most 3 module reads in flight per connector (rest get RATE_LIMITED immediately) so chain reads can never hold the service's 8 connection slots that auth/market need.
after the fix (same synthetic harness): A PRODUCTION_DISABLED, B LOCAL_QA node absent, C LOCAL_QA node live: login -> shell in ~3.3 s, 0 uncaught exceptions, 0 overlay, 1 LOGIN_OK each.
other observations (not caused by this work, not changed): the panel's cold start blocks the FX thread 6-8 s before the login screen (AppContext built on the FX thread: sqlite native load, JNA init, font cascade) and ~2 s of view construction right after login.
