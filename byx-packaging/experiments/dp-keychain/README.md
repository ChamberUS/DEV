# Experimento: modelo de entitlement do keychain de proteção de dados (TEMPORÁRIO)
`dpprobe.c` tenta add/copy/delete de um canário aleatório (nunca impresso) com `kSecUseDataProtectionKeychain`, identidade de TESTE (`invalid.byx-canary-test/…`), assinado em 3 variantes com a identidade Apple Development e Hardened Runtime. Resultados medidos em 2026-10-06 (macOS 26.5.1, Personal Team): v0 sem entitlements → `SecItemAdd=-34018`, `SecItemDelete=-34018`, mas `SecItemCopyMatching=-25300`; v1 (`keychain-access-groups`) e v2 (`+ application-identifier`) sem perfil → `SIGKILL` no lançamento. Nada foi criado no keychain. Para reproduzir: `clang -arch x86_64 -framework Security -framework CoreFoundation -o dpprobe dpprobe.c`, assinar com `codesign --options runtime --entitlements <plist>` e executar.
