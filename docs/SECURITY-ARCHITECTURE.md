# Composição e limites da DEMO

Entrypoint exclusivo: DemoMain -> DemoApp. DemoMain rejeita todos os argumentos. DemoAuthProvider compara somente a identidade pública e cria um registro fixo DEMO_USER/USER; nenhuma credencial ou configuração real é lida. As preferências persistem somente no arquivo local exclusivo da DEMO `~/.byx-mvp-demo/presentation.properties`, com allowlist de idioma, tema, motion, densidade e ícones. Workspace continua TRADING; essa configuração não grava credenciais, tokens, contas ou capacidades. Arquivos inválidos têm fallback seguro. Nenhuma propriedade JVM/variável de ambiente seleciona backend, autoridade ou modo operacional. A JVM continua uma plataforma geral; alterar/injetar código não constitui um modo suportado deste aplicativo nem concede autoridade em serviços reais.

O roteador exige sessão local e uma allowlist fechada. Ocultar Research/BYX é apenas apresentação adicional. Não existem handlers de signer, custody, migração, pesquisa, wallet provisioning, transação, broadcast ou ordem real. O arquivo JAR não contém Main/PanelApp/AppContext originais, nem módulos de autenticação, IPC, SQLite, Service ou pesquisa. O original Main/PanelApp iniciava composição operacional; por isso foi excluído, não adaptado com uma flag.

DemoFixtures gera candles/book/trades e portfolio por funções determinísticas e relógio fixo. Não lê capturas ETHUSDT, não chama redes nem executa processos. Classes de apresentação/DTOs podem conservar vocabulário research/wallet em metadados, CSS ou badges; isso não é um handler operacional. Animações Lottie vêm de recursos locais; a biblioteca recebe uma cópia temporária desses recursos, removida ao terminar. AppInfo só lê versão Java/JavaFX/OS; o shell só usa os.name para apresentação.

Os testes de contrato verificam credenciais, limpeza do char[], USER fixo, logout, fixtures, allowlist, ausência de classes operacionais e rejeição de CLI. A auditoria valida fontes/hashes, classes do JAR, dependências exatas e runtime/licenças; padrões de segredo não equivalem a garantia universal de ausência de vulnerabilidades. O monitor nativo amostra endpoints e filhos da DEMO durante o teste, sem modificar rede ou serviços do sistema.
