Architecture decision: a bounded FX-owned center, closed enum event vocabulary, captured session-generation scopes and allowlisted destinations. No arbitrary localization parameters, raw strings, executable callbacks or API bodies accepted by the event model. UTC event times and stable IDs independent of locale/theme/read state. Maximum 100 rows and 200 remembered identities; chronological newest first, oldest rows evicted; repeated source/type events aggregate within 30 seconds with occurrence counts and retain the event identity. No new timers/executors/polling. Remote state and Service availability displayed separately from collection emptiness. Keyboard/focus use existing overlay host. Legacy constructor with no center remains honestly UNAVAILABLE for existing integration contracts.

Lifecycle finding: the monitor checks its generation before delivering, but an already-delivering callback must also retain its original notification session owner. Added a per-start observer overload to the existing Panel LocalServiceMonitor (same scheduler/probe/period), captured by poll and retry tasks. Account entry stops the old generation before binding the new owner. Old FX deliveries check the captured scope. SessionManager gains a disposable presentation-change observer for logout/account/role invalidation; it performs no authority or Service operation.

Localization finding: direct-key notification messages share some EN phrases with the generic C1 source-copy adapter. Notification-prefixed keys remain in Strings but are excluded from Presentation indexing, so C3 render-time translation cannot change C1 phrase precedence. The unchanged C1 relative-time assertion exposed this in the first full regression; no existing test was relaxed.

UI lifecycle finding: cached Account views must not hold center subscriptions while detached. NotificationCenterView now subscribes only while attached to a Scene, detaches its ListView items/listeners on removal, and removes its scene observer on disposal. This avoids accumulating private-session listeners during account replacement and repeated navigation; closed-surface behavior is checked without depending on GC timing.

Native visual finding: the ListView cell preferred width initially produced a horizontal scrollbar for long descriptions, and DARK used a Modena scrollbar. Cell width now follows the available list width with native scrollbar allowance; description wrapping and scrollbar geometry are checked in both languages/themes. C3-specific scrollbar rules use existing semantic surface/text paints; no C2 palette or global scrollbar contract was changed. Scene reattachment preserves the selected event ID while releasing center subscriptions.
